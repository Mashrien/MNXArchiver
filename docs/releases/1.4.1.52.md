# 1.4.1.52 — Linux MWin menu colors

## Changes

- Menu popups and nested menus inherit the owning MWin renderer. The Linux
  compatibility layer no longer paints its near-white background over that renderer.
- The menu bar now uses the custom item-background and text hooks too. Hover,
  pressed, checked and disabled states retain the configured text colors.
- `mnx.mwin-colors.conf` supports `[MNX.Display.MWin.Menus]` for the menu bar,
  popup background, text and item states, icon margin, borders and separators.
  Missing or invalid menu values inherit the existing main palette, including dark
  palettes. Existing configuration files are not rewritten by the reader.
- Linux MWin is now version **0.0.8.1**. Menu borders use the renderer's actual
  paint bounds, and separator painting is no longer overwritten by the fallback.
- Native Linux executables search beside themselves for shared libraries through
  `$ORIGIN`. A portable user installation can keep `mnx-gui`, `libmnxfile.so.1`,
  `libSkiaSharp.so` and `libHarfBuzzSharp.so` together in `~/.local/bin/` without
  installing the MNX library into a system directory. The engine remains a separate
  shared library.

See [INI configuration](../INI-CONFIG.md) for all menu keys. Restart after editing
the palette. The existing Options switch still disables the custom palette.

## Verification

- Regression reproduced before the fix: generated popup did not inherit MWin's
  renderer, and menu-specific INI colors were unavailable.
- Backend/INI checks cover desktop import, existing palette precedence, menu
  overrides and missing/invalid menu fallbacks.
- Pixel checks open real popup, nested and context-menu controls using the
  offscreen renderer. They cover dark/light backgrounds, icon gutters, borders,
  and normal, hover, checked and disabled text.
- `./build-linux.sh --test` builds the native dual-backend executable and runs
  these checks plus the existing GUI/archive/preview smoke suite.
- Existing dependency, source-link, nullable and Native AOT analysis warnings
  remain; this change does not update the toolchain or third-party dependencies.
